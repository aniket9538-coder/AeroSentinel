1. Executive Scope & Boundary Enforcement 
This document is the official technical handoff for Phase 2 (Fire, Satellite, H3 & Spatial 
Feature Engineering) of Project AeroSentinel. It details the spatial modeling, remote-
sensing ingestion, active fire advection calculations, GIS buffer generation, and non-
leaking feature matrix construction executed by Member 3 (AI / ML + Data + GIS). 
Boundary Enforcement 
• Member 1 (Backend - Java / Spring Boot / PostgreSQL / PostGIS): No Spring 
Boot, Flyway, Hibernate/JPA, or REST controller implementations are included. 
Database interfaces and persistence expectations are documented strictly as 
output contracts. 
• Member 2 (Frontend - React / TypeScript / Vite / MapLibre): No UI, dashboard 
wireframes, map styles, or React state hooks are documented. Geospatial 
requirements are stated solely as JSON/GeoJSON schema specifications. 
• Phase 3 Boundary: No downstream machine learning models (Random Forest, 
LightGBM, neural regressors, or classification heads) were trained in F2. All F2 
deliverables terminate at the construction, profiling, and validation of the feature 
matrices (aligned_environmental.parquet, train_dataset.parquet, 
val_dataset.parquet, test_dataset.parquet).

3. F2-A — Active Fire Processing (NASA FIRMS) 
Implemented in ai-service/preprocessing/fire.py (clean_fire_dataframe(), 
extract_fire_features_for_observation()). 
3.1 Field Normalization & Cleaning 
Raw NASA FIRMS feeds report thermal anomalies detected by polar-orbiting satellite 
passes (VIIRS on Suomi-NPP/NOAA-20, MODIS on Terra/Aqua). 
• Timestamp Handling: The acquisition timestamp (detected_at, acq_datetime) 
is parsed to an ISO 8601 UTC-aware datetime64[ns, UTC]. Observations with 
unparsable timestamps are dropped. 
• Geographic Bounds: Coordinates are checked against valid Earth bounds 
([−90.0,90.0] latitude, [−180.0,180.0] longitude). Points outside are pruned. 
• Confidence Mapping: FIRMS categorical detection confidences are mapped to 
a continuous scale: 
o "low" / "l" → 30.0% 
o "nominal" / "n" → 65.0% 
o "high" / "h" → 90.0% 
o Numeric inputs are validated and clipped to [0.0,100.0]. 
• Fire Radiative Power (FRP): Radiative energy output measured in Megawatts 
(MW). Non-numeric or missing FRP is imputed to 0.0 MW; physical bounds are 
bounded at FRP ≥ 0.0. 
3.2 Scientific Distinction 
Fire detections do not equal ground-level pollution events. A high-FRP fire 20 km 
downwind has negligible impact on a station, whereas a low-FRP fire 5 km upwind 
under stagnant boundary conditions can elevate particulate counts. Features represent 
thermal anomaly proximity and meteorological transport alignment, not confirmed 
pollution causality.

5. Fire Spatiotemporal Alignment & Wind-Aware Advection 
5.1 Temporal Lookback Window 
Fires are episodic, whereas ground air quality is logged continuously. 
• Lookback Span: Exactly 24 hours prior to observation time ([𝑡obs − 24h, 𝑡obs]). 
• Leakage Guard: A fire detected at 𝑡 > 𝑡obs is excluded from the feature 
calculation for observation 𝑡. This isolation is verified by unit test 
test_fire_features_no_future_leakage.

6. F2-B — Sentinel-5P Satellite Feature Extraction 
Implemented in ai-service/preprocessing/satellite.py (clean_satellite_dataframe(), 
extract_satellite_features_for_observation()). 
6.1 Scientific Principles & Satellite Products 
Satellite instruments measure the integrated atmospheric column between the sensor 
and the surface/cloud deck. 
• Distinction: Tropospheric NO2 column density (mol/m2) is not ground-level 
ambient NO2 (𝜇g/m3). It is a vertical optical integration influenced by 
tropospheric chemistry, boundary layer height, and stratospheric separation 
algorithms. 
• Sensors: Sentinel-5P TROPOMI (sun-synchronous low Earth orbit, local 
overpass ~13:30 local solar time). 
6.2 Quality Assurance & Cloud Fraction Filtering 
Optical atmospheric retrievals are degraded by high cloud reflectivity. 
• Cloud Fraction Cutoff: Effective cloud fraction is validated (0.0 ≤ 𝑓cloud ≤ 1.0). 
Observations with 𝑓cloud > 0.30 (30% cloud cover) are flagged as SUSPECT and 
deprioritized during temporal matching to prevent cloud-top artifacts from 
contaminating surface representations.

7.1 Temporal Alignment Logic 
Because polar-orbiting satellites cross a given city once or twice per day, exact hourly 
matches do not exist for every ground observation. 
• Matching Strategy: Each hourly ground record at time 𝑡 queries Sentinel-5P 
overpasses in the historical interval [𝑡 − 24h, 𝑡]. 
• Precedence: Prioritizes observations with exact H3 cell matches and 𝑓cloud ≤
0.30. If multiple overpasses exist, the most recent valid observation is assigned. 
If no cloud-free pass exists within 24 hours, features default to None (imputed as 
regional median during modeling). 
• Leakage Guard: Overpasses occurring at 𝑡sat > 𝑡obs are strictly excluded. 
8. F2-C — Uber H3 Spatial Indexing 
Implemented in ai-service/preprocessing/spatial_alignment.py and ai-
service/preprocessing/spatial_features.py. 
8.1 Resolution Selection 
• Configured Scale: Resolution 8. 
• Geometric Properties: 
o Average hexagon area: 0.7373 km2 (73.7 hectares). 
o Average hexagon edge length: 461.4 meters. 
o Average interior diameter: ≈ 922 meters. 
• Technical Justification: Resolution 8 captures urban neighborhood-scale 
dispersion (traffic corridors, industrial layouts, micro-neighborhoods) without 
producing an overly sparse spatial matrix relative to the physical spacing of 
Pune's monitoring stations (5 to 15 km). 
• API Portability: Both h3 version 3 (h3.geo_to_h3(), h3.k_ring()) and version 4 
(h3.latlng_to_cell(), h3.grid_disk()) are supported dynamically. 
8.2 Boundary and Error Handling 
Validated in test_h3_invalid_and_edge_coordinates: 
• Null, NaN, or non-numeric latitudes/longitudes return None. 
• Out-of-bounds coordinates (e.g., latitude 95.0∘, longitude 195.0∘) return None. 
• Coordinates are rounded to 6 decimal places (~0.11 m) prior to hex assignment, 
preventing floating-point boundary oscillation. 
• Spatial indexing is strictly deterministic: identical coordinates yield identical hex 
strings across runs.
