## 1. Executive Summary

Phase **F7-P6** establishes the complete operational authority lifecycle in AeroSentinel, bridging automated AI triage with authoritative municipal dispatch, ground mitigation, and verified incident closeout.

Prior to F7-P6, alert candidates generated by the F5 triage engine were acknowledged or assigned in isolation without end-to-end domain synchronization. In F7-P6, we implemented the canonical operational lifecycle:
$$\text{OPEN} \longrightarrow \text{ASSIGNED} \longrightarrow \text{IN\_INSPECTION} \longrightarrow \text{ACTION\_TAKEN} \longrightarrow \text{RESOLVED}$$
with the authorized alternate terminal state:
$$\text{OPEN} \ / \ \text{ASSIGNED} \longrightarrow \text{DISMISSED}$$

### Core Architecture Principles Enforced:
1. **Backend Authoritative Validation:** The backend strictly owns lifecycle validation rules via `PollutionEventStatus.isValidTransition()`. The frontend never dictates state transitions; it only requests valid mutations and renders backend truth.
2. **Domain State Synchronization:** Every operational transition executes within a `@Transactional` boundary, updating the parent `PollutionEvent.status` and `Alert.status` atomically.
3. **Dedicated Authority Actions Subsystem:** Built the complete `authority_actions` entity, repository, service, DTOs, and REST controller (`POST /api/v1/actions` and `GET /api/v1/actions`).
4. **Role-Based Authorization:** All operational mutations require `ROLE_AUTHORITY` or `ROLE_ADMIN`. Unauthorized requests from `CITIZEN` or `ANALYST` are strictly rejected with HTTP 403 Forbidden.
5. **Authority UI Readability & UX Hardening:** Completely overhauled `frontend/src/pages/authority/Alerts.tsx` with a high-contrast light theme, 5-step visual lifecycle pipeline, live state-sync explanation, audit trail history panel, context-aware action controls, and confirmation modals with double-submission safety.
6. **Domain Separation & Truth in Labeling:** F3 ML Random Forest, F4 forecast horizons, F5 triage scoring, and F6 Gemini Vision remain completely unmodified and pristine. Citizen reports remain strictly labeled as *Auxiliary Evidence*.

## 2. Canonical Lifecycle State Machine

The operational lifecycle state machine is implemented in `backend/src/main/java/com/aerosentinel/event/PollutionEventStatus.java` and mirrors through `com.aerosentinel.alert.AlertStatus`:

```
                 +-------------------------------------------------+
                 |                                                 |
                 v                                                 |
             +--------+   (Dismiss with reason)               +-----------+
             |  OPEN  | ------------------------------------> | DISMISSED |
             +--------+                                       +-----------+
                 |                                                 ^
                 | Assign Field Team                               |
                 v                                                 |
            +----------+  (Dismiss with reason)                    |
            | ASSIGNED | ------------------------------------------+
            +----------+
                 |
                 | Start Inspection
                 v
         +---------------+
         | IN_INSPECTION |
         +---------------+
                 |
                 | Record Mitigation Action
                 v
          +--------------+
          | ACTION_TAKEN |
          +--------------+
                 |
                 | Resolve with Notes
                 v
            +----------+
            | RESOLVED | (Terminal / Immutable)
            +----------+
```

### Transition Validation Rules:
- `OPEN` $\to$ `ASSIGNED`: Valid when assigning a field team.
- `OPEN` $\to$ `DISMISSED`: Valid with mandatory dismissal reason.
- `ASSIGNED` $\to$ `IN_INSPECTION`: Valid when field inspection begins.
- `ASSIGNED` $\to$ `DISMISSED`: Valid with mandatory dismissal reason.
- `IN_INSPECTION` $\to$ `ACTION_TAKEN`: Valid when authority records first mitigation or enforcement action.
- `IN_INSPECTION` $\to$ `RESOLVED`: **Rejected** (requires recorded mitigation before closeout).
- `ACTION_TAKEN` $\to$ `ACTION_TAKEN`: Valid for recording additional actions.
- `ACTION_TAKEN` $\to$ `RESOLVED`: Valid when resolving incident with mandatory resolution notes.
- Terminal States (`RESOLVED`, `DISMISSED`): Any subsequent mutation attempt throws `IllegalStateException` resulting in HTTP 400 Bad Request.
- State Skips (`OPEN` $\to$ `ACTION_TAKEN`, `OPEN` $\to$ `RESOLVED`, `ASSIGNED` $\to$ `RESOLVED`): Strictly rejected.

## 3. Authority Actions Domain Implementation

To support audit logging of regulatory actions, mobile sensor deployments, and abatement orders, the `authority_actions` domain was fully implemented:

### Entity: `AuthorityAction` (`backend/.../action/AuthorityAction.java`)
- **Table:** `authority_actions`
- **Fields:**
  - `id`: UUID (Primary Key, `@GeneratedValue`)
  - `alert_id`: UUID (Foreign Key to `alerts.id`, indexed)
  - `action_type`: String (`FIELD_VERIFICATION`, `MOBILE_SENSOR_DEPLOYED`, `SITE_CHECK`, `ADVISORY_ISSUED`, `RESOLUTION`, `DISMISSAL`, `OTHER`)
  - `action_details`: String (Mandatory descriptive text)
  - `performed_by`: String (Officer or authority squad identifier)
  - `performed_at`: Instant (Audit timestamp)

### Repository: `ActionRepository` (`backend/.../action/ActionRepository.java`)
- `findByAlertIdOrderByPerformedAtDesc(UUID alertId)`: Retrieves chronological action history for an alert candidate.

### Service: `ActionService` (`backend/.../action/ActionService.java`)
- `@Transactional recordAction(UUID alertId, RecordActionRequest request, String performedBy)`:
  1. Validates alert existence.
  2. Resolves parent `PollutionEvent`.
  3. Validates current event status is `IN_INSPECTION` or `ACTION_TAKEN`.
  4. Advances event status to `ACTION_TAKEN`.
  5. Persists `AuthorityAction`.
  6. Returns `ActionResponseDto`.
- `getActionsForAlert(UUID alertId)`: Returns list of DTOs.

### Controller: `ActionController` (`backend/.../action/ActionController.java`)
- `POST /api/v1/actions`: Enforces `@PreAuthorize("hasAnyRole('AUTHORITY', 'ADMIN')")`. Records new mitigation action.
- `GET /api/v1/actions?alertId={uuid}`: Returns list of actions.

## 4. Event/Alert State Synchronization Matrix

| Operation | Trigger Endpoint | Event Status Transition | Alert Status Transition | Audit Action Created |
| :--- | :--- | :--- | :--- | :--- |
| **Acknowledge** | `PATCH /api/v1/alerts/{id}/acknowledge` | `OPEN` (Unchanged) | `OPEN` $\to$ `ACKNOWLEDGED` | - |
| **Assign Team** | `POST /api/v1/inspections/assignments` | `OPEN` $\to$ `ASSIGNED` | `ACKNOWLEDGED` | `FIELD_VERIFICATION` (Assigned) |
| **Start Inspection** | `POST /api/v1/inspections/{id}/start` | `ASSIGNED` $\to$ `IN_INSPECTION` | `ACKNOWLEDGED` | - |
| **Record Action** | `POST /api/v1/actions` | `IN_INSPECTION` $\to$ `ACTION_TAKEN` | `ACKNOWLEDGED` | Action recorded (e.g. `MOBILE_SENSOR_DEPLOYED`) |
| **Field Verification** | `POST /api/v1/inspections/{id}/verification` | Maintains current status | `ACKNOWLEDGED` | Verification recorded |
| **Resolve Alert** | `PATCH /api/v1/alerts/{id}/resolve` | `ACTION_TAKEN` $\to$ `RESOLVED` | `ACKNOWLEDGED` $\to$ `RESOLVED` | `RESOLUTION` (with closeout notes) |
| **Dismiss Candidate** | `PATCH /api/v1/alerts/{id}/dismiss` | `OPEN` / `ASSIGNED` $\to$ `DISMISSED` | `OPEN` / `ACKNOWLEDGED` $\to$ `DISMISSED` | `DISMISSAL` (with dismissal reason) |

## 11. Security Audit

1. **JWT Role Claims:** JWT tokens include standard user roles (`ROLE_AUTHORITY`, `ROLE_ADMIN`, `ROLE_CITIZEN`, `ROLE_ANALYST`).
2. **Authority Token Extraction:** `JwtAuthenticationFilter` inspects the `role` claim and populates Spring `SecurityContextHolder`.
3. **Endpoint Gatekeeping:** All write operations on `/api/v1/actions/**`, `/api/v1/inspections/**`, and `/api/v1/alerts/{id}/(acknowledge|resolve|dismiss)` require `ROLE_AUTHORITY` or `ROLE_ADMIN`.
4. **Access Denied Translation:** `GlobalExceptionHandler` converts `AccessDeniedException` into RFC 7807 compliant error payload with HTTP 403 Forbidden.
5. **Double-Submit Prevention:** Client UI state disables all mutation buttons while `actionInProgress` is true.

## 12. Data Integrity & Database Schema

### Table: `authority_actions`
```sql
CREATE TABLE IF NOT EXISTS authority_actions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    alert_id UUID NOT NULL REFERENCES alerts(id) ON DELETE CASCADE,
    action_type VARCHAR(64) NOT NULL,
    action_details TEXT NOT NULL,
    performed_by VARCHAR(255) NOT NULL,
```
